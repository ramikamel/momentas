# Demo creation flow implementation plan

User explicitly requested: remove the image request limit, expose saved pictures, and allow Submit to generate directly while Add details optionally opens scene editing.

Implementation decisions: no new schema or credentials. Rendering accepts an uncapped application policy while retaining existing atomic pending/idempotency safeguards; the existing PostgreSQL RPC uses its maximum int value for compatibility rather than requiring another schema migration. Old MAX_IMAGE_REQUESTS is ignored. Provider rate limits still surface as retryable service errors. The private Saved pictures page discovers existing owner cookies server-side and validates each one before returning any data. It groups every image version by memory, with a direct link that selects the correct version. No global or unauthenticated memory list.

Homepage Submit creates/reuses the same private draft then performs extraction and generation through an owner-only API before navigating to the image. Add details saves/extracts and opens the optional editor. A failed generation preserves a visible Open saved draft link and can be retried without another draft. Voice-first workspace offers the same direct-generation path. Submission itself authorizes generation, with no mandatory review checkbox. Original scene-source validation and deliberate publication remain.
